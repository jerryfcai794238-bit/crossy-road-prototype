# 展示型 GDD HTML 品質門檻 v1

## 1. 定位與使用方式

本文件是 `docs/過馬路GDD.html` 的內部品質閘門；它同時檢查兩件事：

- **規格性**：企劃與工程可依文件得到相同的實作結論。
- **展示性**：零背景讀者可快速理解【休閒模式】怎麼玩、為何有趣。

本輪以 **4 分**為正式呈現通過門檻；**5 分**為後續標竿，不是第一輪必達。

## 2. 零背景理解測試（權重 25%，硬性門檻）

### 測試條件

測試者不得參與本輪修改、不得先看原始規格、不得接受口頭說明。首次閱讀僅聚焦【休閒模式】。

| 階段 | 任務 |
| --- | --- |
| 45 秒 | 閱讀首頁、總覽與核心循環，可自然捲動。 |
| 3 分鐘 | 閱讀 Ch3，並操作一次推擠沙盒。 |
| 必答 1 | 這局玩家的目標是什麼？ |
| 必答 2 | 玩家怎麼移動？前方有人時會怎樣？ |
| 必答 3 | 為何要看車、河道與安全區？ |
| 必答 4 | 休閒模式失誤後會發生什麼？排名如何變化？ |

### 評分

| 分數 | 條件 |
| ---: | --- |
| 1 | 說不出遊戲目標或玩法。 |
| 2 | 只知道有車、河與多人，無法說明規則。 |
| 3 | 知道目標與 WASD，但不知道推擠或復活／排名後果。 |
| 4 | 正確回答四題，且能完成一次沙盒操作。 |
| 5 | 能預測應等待或推擠、推入危險區的結果與原因。 |

## 3. 品質評分量表

| 項目 | 權重 | 1 分 | 2 分 | 3 分 | 4 分：正式呈現門檻 | 5 分：標竿 |
| --- | ---: | --- | --- | --- | --- | --- |
| 閱讀結構 | 15% | 必須讀長文 | 有標題但混雜 | 有卡片與收合 | 30 秒懂賣點、3 分鐘懂玩法、細節按需展開 | 不同職能可直接跳至所需深度 |
| 視覺語言與 Present 節奏 | 15% | 像 Markdown／全同色 | 僅裝飾色 | 有色彩但卡片重複 | 動作、規則、安全、危險有固定色彩；章節表現有節奏 | 可直接跨職能展示，視線自然落在重點 |
| 圖像化解釋 | 15% | 複雜規則沒有圖或圖錯 | 圖為裝飾 | 核心圖正確但普通 | 核心循環、危險、模式差異可看圖理解 | 形成一致遊戲視覺敘事，圖與規格完全一致 |
| 互動教學價值 | 10% | 壞掉或無關 | 有按鈕但無結果 | 一項規則可操作、可重設 | 難以文字理解的規則有最小示範，狀態與原因可見 | 30 秒互動即可理解取捨，結果可追至規格 |
| 規格可實作性 | 15% | 矛盾或缺規則 | 模式／例外不清 | 主規則可實作 | 每項複雜機制具觸發、判定、結果、例外與驗收 | 企劃與工程獨立閱讀後得到同一實作結論 |
| 響應式與可用性 | 5% | 裁切或不可操作 | 僅單一尺寸可用 | 可用但擁擠 | 1440px 與 390px 無裁切；目錄、鍵盤、替代文字可用 | 各尺寸均保留閱讀層次，適合截圖與分享 |

## 4. 固定視覺與互動標準

| 類別 | 必要條件 |
| --- | --- |
| 視覺基礎 | 不使用漸層、光暈、模糊陰影或大面積純白底色。一般文字對比至少 `4.5:1`。 |
| 語意色彩 | 至少四種固定語意色：動作／時間、規則／系統、安全／復活、危險／失誤。顏色必須傳達內容，不可只裝飾。 |
| 展示卡片 | 展示區至少使用三種卡片角色底色；避免只靠換色重複相同卡片版型。 |
| 核心循環 | 使用「無文字視覺底圖 + SVG／HTML 精準中文與箭頭」的混合形式；AI 圖不得承擔任何必要文字或規則。 |
| Ch3 推擠沙盒 | 維持 10 格；危險放在右側後段；首次阻擋或落水必須在最多第 4 次操作出現。 |
| 保留互動 | 每個互動必須有初始狀態、操作、可見結果、原因提示與重設；非教學性的互動一律刪除。 |
| 規格呈現 | 複雜機制以「觸發 → 判定順序 → 結果 → 例外 → 驗收」呈現；正式規格與尚未完成的原型差異必須清楚區隔。 |

## 5. 通過與檢核流程

| 項目 | 規則 |
| --- | --- |
| 正式呈現門檻 | 加權平均至少 `4.2 / 5`，且所有項目至少 4 分。 |
| 強制退件 | 零背景理解低於 4、規格可實作性低於 4、圖與規格矛盾、互動錯誤、桌面或手機裁切。 |
| 企劃／Present 審核 | 閱讀結構、視覺語言、圖像化解釋與展示節奏。 |
| 工程審核 | 規格、公式、模式差異、互動結果與驗收例。 |
| 獨立讀者審核 | 執行 45 秒與 3 分鐘的理解測試。 |
| 修改前提 | 每次報告皆須列出「目前分數 → 目標分數 → 證據 → 扣分原因 → 對應修改」；沒有明確扣分依據，不進行改動。 |

## 7. 預設範圍

- 首次理解聚焦【休閒模式】；讀者理解基本玩法後，再進入挑戰模式。
- 本標準僅作為內部品質閘門，不新增到玩家／工程日常閱讀的 GDD 章節中。
